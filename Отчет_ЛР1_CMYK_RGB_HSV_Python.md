## 1. Введение

**Цель работы:** изучить цветовые модели RGB, CMYK и HSV, реализовать преобразования между ними и разработать графическое приложение, позволяющее задавать цвет разными способами с автоматическим обновлением его представлений.

**Задачи:**

1. Изучить назначение и диапазоны компонентов моделей RGB, CMYK и HSV.
2. Реализовать преобразования RGB ↔ CMYK и RGB ↔ HSV.
3. Создать интерфейс с числовыми полями, ползунками, палитрой выбора цвета и HEX-представлением.
4. Обеспечить пересчёт всех моделей при изменении цвета в любой из них.
5. Проверить работу приложения на основных и граничных значениях.

## 2. Используемые технологии

Приложение реализовано на языке **Python** с использованием встроенной библиотеки **`tkinter`** для создания графического интерфейса. Модуль `colorchooser` используется для открытия системного диалога выбора цвета. Для выполнения математических преобразований применяются стандартные арифметические операции Python; сторонние библиотеки не требуются.

Основные элементы интерфейса:

- поля точного числового ввода;
- ползунки `Scale` для изменения компонентов;
- кнопка выбора цвета через системную палитру;
- поле ввода HEX-кода;
- область предпросмотра текущего цвета.

## 3. Математические основы преобразований

### 3.1. RGB → CMYK

Значения каналов RGB задаются в диапазоне от 0 до 255. Для вычислений они нормируются к диапазону \([0,1]\):

\[
r = \frac{R}{255}, \qquad
g = \frac{G}{255}, \qquad
b = \frac{B}{255}.
\]

Чёрная компонента вычисляется по формуле:

\[
K = 1 - \max(r,g,b).
\]

Если \(K=1\), цвет является чёрным. В этом случае компоненты \(C\), \(M\) и \(Y\) принимаются равными нулю. В остальных случаях:

\[
C = \frac{1-r-K}{1-K},
\]

\[
M = \frac{1-g-K}{1-K},
\]

\[
Y = \frac{1-b-K}{1-K}.
\]

В программе компоненты CMYK отображаются в процентах, поэтому полученные значения умножаются на 100.

### 3.2. CMYK → RGB

Компоненты CMYK вводятся в процентах и перед вычислением нормируются к диапазону \([0,1]\). Каналы RGB рассчитываются следующим образом:

\[
R = 255(1-C)(1-K),
\]

\[
G = 255(1-M)(1-K),
\]

\[
B = 255(1-Y)(1-K).
\]

Результирующие каналы округляются до целых значений от 0 до 255.

### 3.3. RGB → HSV

Сначала значения RGB нормируются к диапазону \([0,1]\). Обозначим:

\[
M_x = \max(r,g,b), \qquad
M_n = \min(r,g,b), \qquad
\Delta = M_x-M_n.
\]

Компонента **V (Value)** определяет значение яркости:

\[
V=M_x.
\]

Насыщенность **S (Saturation)** вычисляется по формуле:

\[
S =
\begin{cases}
0, & M_x=0,\\
\frac{\Delta}{M_x}, & M_x>0.
\end{cases}
\]

В приложении \(S\) и \(V\) отображаются в процентах.

Оттенок **H (Hue)** зависит от максимального RGB-канала:

\[
H =
\begin{cases}
0, & \Delta=0,\\
60\left(\left(\frac{g-b}{\Delta}\right)\bmod 6\right), & M_x=r,\\
60\left(\frac{b-r}{\Delta}+2\right), & M_x=g,\\
60\left(\frac{r-g}{\Delta}+4\right), & M_x=b.
\end{cases}
\]

Оттенок измеряется в градусах. В программе он приводится к диапазону от 0° до 360°.

### 3.4. HSV → RGB

При обратном преобразовании оттенок \(H\) приводится к диапазону \([0,360)\), а значения \(S\) и \(V\) переводятся из процентов в диапазон \([0,1]\).

Вычисляются промежуточные величины:

\[
C=V\cdot S,
\]

\[
X=C\left(1-\left|\left(\frac{H}{60}\bmod 2\right)-1\right|\right),
\]

\[
m=V-C.
\]

В зависимости от сектора оттенка выбирается промежуточная тройка каналов:

| Диапазон H | Промежуточные значения \((R',G',B')\) |
|---|---|
| \(0° \le H < 60°\) | \((C,X,0)\) |
| \(60° \le H < 120°\) | \((X,C,0)\) |
| \(120° \le H < 180°\) | \((0,C,X)\) |
| \(180° \le H < 240°\) | \((0,X,C)\) |
| \(240° \le H < 300°\) | \((X,0,C)\) |
| \(300° \le H < 360°\) | \((C,0,X)\) |

Затем к каждому каналу прибавляется \(m\), результат умножается на 255 и округляется до целого числа.

## 4. Архитектура и логика приложения

Приложение организовано в виде класса `ColorApp`. Для хранения текущего цвета используется атрибут `current_rgb`, содержащий три целочисленных значения RGB.

Преобразования вынесены в отдельные функции:

- `rgb_to_cmyk()` — перевод RGB в CMYK;
- `cmyk_to_rgb()` — перевод CMYK в RGB;
- `rgb_to_hsv()` — перевод RGB в HSV;
- `hsv_to_rgb()` — перевод HSV в RGB.

После изменения значения в любой модели программа получает соответствующий RGB-цвет. Метод `update_from_rgb()` пересчитывает компоненты CMYK и HSV, обновляет поля ввода, ползунки, HEX-код и область предпросмотра.

Для предотвращения повторного вызова обработчиков во время программного обновления элементов используется флаг `_updating`. При изменении ползунков применяется небольшая задержка с помощью `root.after()`, что уменьшает число пересчётов во время движения.

**Особенность реализации:** RGB используется как единое основное состояние цвета. Поэтому исходные значения других моделей могут немного изменяться после преобразования и обратного пересчёта. Например, при \(K=100\%\) компоненты \(C\), \(M\) и \(Y\) не влияют на итоговый RGB-цвет, поэтому их исходные значения невозможно восстановить только по RGB.

## 5. Пользовательский интерфейс

Интерфейс включает следующие элементы:

1. **Область предпросмотра** — отображает выбранный цвет, его HEX-код и значения RGB.
2. **Выбор цвета из палитры** — кнопка открывает системный диалог выбора цвета.
3. **Ввод HEX-кода** — позволяет задать цвет в формате `#RRGGBB`. Также поддерживается сокращённая запись из трёх шестнадцатеричных символов, например `#F00`.
4. **Блок RGB** — поля и ползунки для компонентов R, G и B в диапазоне 0–255.
5. **Блок CMYK** — поля и ползунки для компонентов C, M, Y и K в диапазоне 0–100%.
6. **Блок HSV** — поля и ползунки для H (0–360°), S (0–100%) и V (0–100%).

После изменения компонента программа автоматически обновляет остальные представления цвета и предпросмотр.

## 6. Проверка работы и ограничения

Для проверки преобразований можно использовать следующие цвета:

| Цвет | RGB | Ожидаемый результат |
|---|---|---|
| Красный | `(255, 0, 0)` | HSV ≈ `(0°, 100%, 100%)`; CMYK ≈ `(0%, 100%, 100%, 0%)` |
| Белый | `(255, 255, 255)` | HSV: S = 0%, V = 100%; CMYK: K = 0% |
| Чёрный | `(0, 0, 0)` | HSV: S = 0%, V = 0%; CMYK: K = 100% |
| Серый | `(128, 128, 128)` | HSV: S = 0%; оттенок визуально не определён |

При тестировании следует проверить изменение цвета через каждую модель, перемещение ползунков, выбор цвета из палитры и ввод HEX-кода.

Диапазоны допустимых значений:

- RGB: от 0 до 255;
- CMYK: от 0 до 100%;
- H: от 0° до 360°;
- S и V: от 0 до 100%.

**Ограничения реализации:**

- CMYK рассчитывается по упрощённой математической модели и не учитывает ICC-профили принтера.
- RGB хранится в виде целых чисел, поэтому при преобразованиях возможны небольшие расхождения из-за округления.
- Для белого, чёрного и серых цветов оттенок HSV визуально не определён. В реализации при равенстве всех RGB-каналов устанавливается \(H=0\).
- Поскольку основным состоянием является RGB, неоднозначные исходные значения CMYK или HSV могут нормализоваться при пересчёте.

## 7. Выводы

В ходе лабораторной работы разработано графическое приложение на Python для работы с цветовыми моделями CMYK, RGB и HSV. Реализованы преобразования RGB ↔ CMYK и RGB ↔ HSV. Пользователь может выбирать цвет через системную палитру, вводить HEX-код, использовать числовые поля и ползунки.

При изменении компонента программа автоматически пересчитывает представления цвета во всех трёх моделях и обновляет область предпросмотра. Реализация демонстрирует различия между аддитивной моделью RGB, субтрактивной моделью CMYK и моделью HSV, разделяющей цвет на оттенок, насыщенность и значение яркости.

В дальнейшем приложение можно улучшить за счёт независимого хранения исходных координат каждой модели, добавления автоматических тестов и поддержки цветовых профилей.
